# dsh-feishu-panel

DSH 设置里的「飞书」页：把 [dsh-feishu-card](../dsh-feishu-card) 的配置项从 JSON 文件搬进图形界面。

- **总开关**：启用/停用飞书桥（热生效，无需重启）
- **会话映射**：每个会话独立飞书群 / 话题模式 / 平铺
- **弹窗位置**：审批与提问只在飞书，或飞书与桌面双通道
- **流式与刷新**：卡片开关、刷新间隔、并发数、卡片宽度
- **展示内容**：执行过程、思考预览与保留、页脚统计、多选样式
- **登录与凭据**：扫码登录（设备码 + 二维码）、浏览器授权、App ID / Secret 配置
- **授权检查**：用户 scope 是否齐全、应用权限缺哪些，缺的一键补齐
- **运行状态**：飞书身份、卡片回调次数、已映射会话/群、最近错误
- **操作**：重新读取、保存、发送测试消息

## 登录怎么工作

面板使用飞书官方的 **OAuth 设备码流程**（与 `lark-cli auth login` 相同）：

1. 点「扫码 / 浏览器授权」→ Host 调用 `auth login --no-wait` 拿到验证链接与设备码；
2. Host 用 `auth qrcode` 把链接转成二维码 PNG，页面直接显示；
3. 用飞书 App 扫码（或点「在浏览器打开」）→ 手机确认授权；
4. Host 后台进程用 `--device-code` 完成换取 token，页面每 2 秒轮询一次状态，成功后自动刷新身份。

授权检查分两类，处理方式不同：

| 类别 | 谁能给 | 面板能力 |
| --- | --- | --- |
| **用户 scope**（代表你操作） | 你自己，设备码授权 | 一键补齐：只申请缺的那几个 scope，出二维码 |
| **应用权限**（机器人身份） | 企业管理员，开放平台审批 | 只读探测 + 一键跳转申请页（链接已预填缺口 scope） |

## 它是怎么工作的

```
设置页 (Client)  ──fetch──▶  Host 路由 /feishu-panel/*  ──读写──▶  ~/.dsh/feishu-card.json
                                                                  ~/.dsh/feishu-card.secret.json（只读判断是否存在）
                                                                  ~/.dsh/feishu-card-bindings.json
```

- 配置项由 Host 的**声明式 schema** 定义，Client 按 schema 渲染；新增一项配置只改 `index.js` 的 `SCHEMA`，不用动前端。
- 面板只读写桥本来就读取的那个 `feishu-card.json`，**不改变桥的任何行为**。
- 三条路由只接受**回环地址**（127.0.0.1 / ::1），且不返回任何密钥内容。

## 安装

```powershell
# 在 DSH 里：Plugins → Add plugin → 选择本目录
# 或在终端：
dsh plugin add <本目录>
```

安装后重启 DSH，设置面板出现「飞书」页。

## 生效时机

桥在**启动时**读取配置，所以保存后面板会提示「重启 DSH 生效」。

## 安全

- 面板不显示 App Secret，只显示「已配置 / 未配置」；
- 路由仅回环可访问，拒绝跨站请求读取；
- 「发送测试消息」用机器人身份给你自己发一条 Markdown，不经过模型。
