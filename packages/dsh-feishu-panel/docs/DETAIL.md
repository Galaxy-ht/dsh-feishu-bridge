# 飞书桥控制面板

## 为什么需要它

`dsh-feishu-card` 的行为由 `~/.dsh/feishu-card.json` 决定：会话是一会话一群还是话题、审批弹窗出现在哪、卡片刷多快、显示哪些内容。手改 JSON 容易写错键名，也看不到当前飞书身份、回调是否生效、有没有报错。

这个面板把这些全部图形化：左边是分组的开关与数值，右边是运行状态，底部提示「重启 DSH 生效」。

## 页面结构

| 分组 | 内容 |
| --- | --- |
| 会话映射 | 每个会话独立飞书群、话题模式、审批弹窗位置 |
| 流式与刷新 | 互动卡片开关、最小刷新间隔、并发更新数、卡片宽度 |
| 展示内容 | 执行过程面板、思考预览、保留思考、页脚统计、多选样式 |
| 高级 | 首次建卡延迟、单卡字节预算、启动补发 |
| 运行状态 | 机器人/用户身份、卡片回调次数、已映射会话与群、最近错误 |

## 设计

- **声明式 schema**：配置项在 Host 的 `SCHEMA` 里声明（键、类型、范围、中英文案），Client 只负责按 schema 渲染。新增配置 = 加一段声明。
- **单一事实源**：面板读写的仍是桥启动时读取的那个 JSON，不引入第二份配置。
- **只读状态**：身份与计数来自 `lark-cli auth status` 和桥的 bindings 文件；App Secret 只判断存在与否，不读取内容。
- **回环限定**：`/feishu-panel/*` 只接受 127.0.0.1 / ::1。

## 限制

- 配置在桥启动时读取，保存后需重启 DSH。
- 面板不提供飞书登录能力；身份异常时按提示在终端执行 `lark-cli auth login`。
- 「发送测试消息」直接调用飞书 OpenAPI 的机器人身份，不消耗模型额度。
