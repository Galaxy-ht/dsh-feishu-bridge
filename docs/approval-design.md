# 飞书卡片审批需求清单（动手前必读）

> 每次改动前先对照本文件；任何演示都**必须**落在当前回合那张卡片里，不新建消息。

## 一、整体交付

1. 一个新插件 `dsh-feishu-card`：交互顺畅、消息美观。
2. 流式输出：直连 OpenAPI 拿更新频率 + CardKit 打字机。
3. 会话 1:1：每个 DSH 会话一个独立飞书群（`sessionChats`），不用话题；群里直接说话即继续。
4. 提问与审批都在飞书卡内；`feishuOnly` 时关闭桌面弹窗。
5. 多题一卡、一次提交；多选下拉返回数组。
6. 控制面板 `dsh-feishu-panel`：配置项、扫码/浏览器登录、授权检查。

## 二、审批卡片（合并进消息卡）

7. **审批块插入当前回合那张卡**，横线下方；绝不新增消息或第二张卡。
8. 待确认块**永不折叠**；已答块压成一行。
9. 已答记录在回合结束时并入「审批记录（N）」折叠面板。
10. 按钮布局：
    - 第一行：`允许` / `拒绝` / `取消`，三个**等宽**按钮；
    - 第二行：`信任本会话`，**通栏**并与上面三个对齐。
11. 按钮文案 ≤6 字；每行最多 3 个，等宽铺满，不允许截断（`width: weighted + fill`）。
12. `信任本会话` 语义 = 切换到客户端**完全权限**（会话级提权）：
    - 点击后**其余未点的审批项一并变成允许**；
    - 卡片显示「🔓 本会话已切换到完全权限」。
13. 未完成的审批要**跨卡携带**：新回合卡片创建时，把仍未答的审批块带到新卡顶部。
14. 并发多审批各自独立块，互不覆盖；数量变化时批量按钮的计数要同步重算。

## 三、演示与验证规则（对 AI 的约束）

15. **所有演示必须插进当前回答的卡片**，一律不新建消息（此前多次犯）。
16. 演示按钮必须**真能点**（点击 → 卡片原地更新），不接受"按钮不生效"的静态预览。
17. 演示前先读本清单；演示后对照清单逐条确认。
18. 改代码前先说明将改动哪些文件；改完必须语法校验。

## 四、已知技术事实

- CardKit 元素接口：`POST /cards/:id/elements`（`elements` 必须是 JSON **字符串**，每个组件带自定义 `element_id`）、`PUT /cards/:id/elements/:element_id`（`element` 同样字符串化）。
- 同一张卡的 `sequence` 必须严格递增；流式期间由插件独占，外部写入会打乱顺序 → 演示要等回合结束后再插。
- DSH 审批 outcome 只有 `allowed-once | rejected | cancelled | unavailable`；「信任本会话」需通过 `permissionPresets.set(session, <full>)` 切换预设实现。
- 飞书卡片按钮在 `column_set` 里用 3 个 `width: weighted + fill` 可等宽；超过 3 个或标签过长会截断。
